## AI 聊天與頻道記憶（2026/10/14）

- 文字 AI 問答可用 tag Tourist，或直接回覆 Tourist 的訊息（關閉回覆通知也可）；兩者都讀同頻道近期訊息與被回覆內容。回覆其他人的訊息仍需 tag；同語音頻道用語音回答，其餘回文字。
- 先進入伺服器的語音頻道，執行 `/加語音`，Tourist 會加入但不播音樂，成功只回覆 `OK`；然後在文字頻道 tag Tourist 即可語音問答，使用 `/離開` 結束。已在同一語音頻道時沿用連線，不自動跨頻道移動。加入時檢查 Connect／Speak、discord.py 版本與 DAVE 依賴，20 秒 timeout、不自動重連；Terminal 的 `[Voice]` 紀錄包含語音狀態、成功／失敗與 WebSocket code。
- 語音套件要求 `discord.py[voice]>=2.7.1,<3`、`discord-ext-voice-recv==0.5.2a179`，包含 davey；在 bot 實際 Python 環境執行 `python -m pip install -U -r requirements.txt`，再重啟 bot 同步 slash commands。可用 `python -m discord --version` 檢查語音依賴。更新後先 `/離開` 再 `/加語音`，建立支援收音的連線。`/唱歌` 的 YouTube 搜尋／播放流程依使用者要求暫不處理；反覆進出原因尚未在故障主機確認。

- tag 的使用者與 Tourist 在同一語音頻道且未播放／暫停音樂時，優先使用 `gemini-3.1-flash-live-preview` 依使用者指定語言及活動情境產生語音（可使用英文），思考量設為 `minimal`，成功時只播放語音、不傳送文字轉錄。語音回覆共用隊列，上一段播完才處理下一段；tag 的人不在該語音頻道則回文字。Live 走獨立 API，不加入原本 7 個文字／摘要模型池；失敗或正在播音樂時退回原文字流程。已停用 1% 自動回覆。
- 音色固定為 Fenrir；只能修改 `gemini_live.py` 的 `DEFAULT_LIVE_VOICE` Python 常數並重啟。沒有 /音色 指令、環境變數或資料庫音色覆寫。
- 文字頻道歷史仍只在 tag 時讀同一頻道最近 50 則，不自動加入／切換語音頻道。已連線語音模式下，問候、身分詢問等 tag 也交給 Live 回答；原本音樂不會被中斷。
- `/加語音` 會開始接收該語音頻道的麥克風，依 Discord 使用者 ID 分開收音，約一秒停頓後交給文字模型池轉錄及判斷是否需要回答；多人都可直接對話，沒有固定喚醒詞。模型判斷可能誤把聊天當成提問，或漏掉短句。等待隊列最多 8 段；滿時丟棄新進音訊並記錄警告。播放音樂時暫停處理麥克風，Tourist 說話期間仍可收集人聲排隊。
- 麥克風原始音訊僅暫存在記憶體，不寫入檔案；轉錄與 Tourist 回覆私下存入 SQLite，回答時讀同語音頻道最近 50 筆、最多 12,000 字元。語音頻道彼此隔離，不背景讀取文字頻道歷史；`/離開` 停止收音並清掉待處理音訊。
- 收音套件目前為 alpha；程式針對固定版本加上 discord.py DAVE session 解密相容層。已通過模擬測試及本機套件介面檢查，尚未驗證實際 Discord 加密收音。這是分段轉錄後再產生語音，尚非連續雙向 Live 串流，也不支援打斷正在播放的回答。
- 更新依賴 `pip install -r requirements.txt`（新增 `google-genai`），主機需要 FFmpeg；Windows 使用 `bin/ffmpeg.exe`，Linux 使用 PATH 的 `ffmpeg`。Live 收取單次完整語音後播放，timeout 60 秒、原始 PCM 上限 8 MiB；輸出用 FFmpeg 編碼為 Opus。需具備語音頻道 Connect／Speak 權限，API key 也須能使用 Live 模型。

- 已停用未 tag 文字訊息的 1% AI 自動回覆；文字問答只在 tag 時觸發，已加入的語音頻道可直接開口互動。原本關鍵字貼圖／表情互動仍保留。

- 每次文字／圖片問答隨機排序 7 個模型：`gemini-2.5-flash`、`gemini-2.5-flash-lite`、`gemini-3-flash-preview`、`gemini-3.5-flash-lite`、`gemini-3.1-flash-lite`、`gemma-4-26b-a4b-it`、`gemma-4-31b-it`。任何 HTTP 錯誤、網路錯誤、逾時或無有效回答時換下一個，各模型每次最多嘗試一次；成功即停止，全部失敗才通知使用者。每次請求 timeout 60 秒。
- Terminal 印出台灣時間（+08:00）、用途（chat／memory／listen）、模型名稱、成功／失敗及 HTTP 狀態或錯誤類別，不印 API key。記憶摘要也使用此模型池，JSON 格式無效時會換模型。文字／圖片問答 temperature 為 1.6。
- 只有 tag Tourist 並進入 AI 問答時，才讀取及保存這次的最近訊息至 `data/chat_memory.sqlite3`；其中包含沒 tag 的人類對話及之前 Tourist 的回覆。不逐則背景保存、不定時讀取歷史。頻道與討論串各自獨立；其他機器人的訊息不納入 AI 記憶。
- 被 tag 且進入 AI 問答流程時，從 Discord 讀取同頻道最近 50 則訊息，按時間排列，最多 24,000 字元；近期附件只提供檔名，當前訊息的第一張圖片會另外傳給模型。
- 回覆同頻道的一則訊息並 tag Tourist 時，另外提供原訊息的作者、文字（最多 12,000 字元）及附件檔名，即使原訊息已超出最近 50 則。沒有快取時依訊息 ID 讀取；已刪除或沒有權限則註明無法讀取。引用附件目前只提供檔名，不自動解析圖片或檔案內容。
- 同一次 AI 問答觸發該頻道的摘要檢查，保留最新 50 則；較舊的未摘要訊息累積至少 30 則時，每批最多 100 則交給模型整理。摘要只讀取每則前 2,000 字元，但原文會完整用 zlib 壓縮歸檔。模型選出的重要訊息另保留完整原文及檢索索引。摘要失敗時保留原始資料，等下次 tag 時重試。
- 回答前以 SQLite FTS5／BM25 檢索同頻道摘要、重要原文與尚未摘要的原文；中文使用雙字切詞。最多取 6 筆、10,000 字元，與近期內容一併提供給模型，不把整份歷史放進 prompt。這是關鍵字檢索，尚未使用 embedding，對同義詞的匹配能力有限。
- 記憶只累積每次 tag 時取得的最近 50 則快照；兩次 tag 間若超過 50 則，較早訊息可能不會保存。不自動匯入所有既有歷史。資料庫重啟後保留且被 Git 忽略，換機需另行備份／搬移。壓縮歸檔目前作還原備份，不直接參與全文檢索；重要性由模型判斷，可能遺漏。
- 保存的是收到當下的快照，目前不同步 Discord 訊息編輯／刪除，不會自動清除舊資料。僅保存文字與附件檔名，不備份附件檔案。

部署時確保 Developer Portal 的 **Message Content Intent** 已啟用，並授予 Tourist 頻道的 **View Channel** 和 **Read Message History** 權限。程式已使用 `discord.Intents.all()`。摘要也會消耗 Gemini 額度；切換模型不保證避開帳號／專案共用限制。

驗證：`python -m unittest discover -s tests -v`；語法檢查：`python -m py_compile chat_memory.py gemini_live.py cogs/chat.py`。
- tag 觸發的語音也使用同文字頻道的近期 50 則、相關記憶及過往語音回覆；成功播放後把語音轉錄私下保存到 SQLite `voice_replies`，不貼到聊天室。下次 tag 時納入背景，並可檢索較舊語音內容，頻道／討論串仍隔離。麥克風對話使用獨立的語音頻道上下文，可延續 Tourist 在該語音頻道剛提出的英聽問題。
